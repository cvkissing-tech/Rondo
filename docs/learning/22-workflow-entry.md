# 22：执行入口为什么会随着计划消失

此前的小窗口布局会用完整计划替换聊天区，而“采用计划并执行”按钮恰好属于聊天底部。隐藏聊天时，按钮一起被隐藏。后台自动执行、审查和一次返修的代码没有删除，但用户失去了明显的启动入口。

修复是把任务级动作移到两个面板的共同父级，继续使用Jean按钮和现有主题：

```text
task-workbench
  WorkflowBar：实际状态、协作顺序、采用当前版本并执行
  ResizablePanelGroup
    TaskTimeline：讨论与进展
    WorkspaceInspector：计划、文件、改动、会话
```

`WorkflowBar.tsx`继续调用原来的`startExecution`，没有另写自动工作流引擎。采用版本的后台核对、执行、检查、审查和至多一次返修沿用原实现。聊天里不重复放同一个执行按钮。

另一个相关问题是已读取的差异会抢占`taskFlow`分支：一份针对当前代码的有效计划，本来应能执行，却因查看过改动而被引向人工审查。现在只有没有计划时，差异才走这个兜底分支；计划过期和旧执行收据继续保留原来的阻断行为。

`flow-check.mjs`包含这个有意义的回归：有当前计划、同时已读取差异，动作仍为execute。`workflow-entry-smoke.mjs <ready-task-id> [database]`只读备份指定数据库，在独立Electron配置下核对入口可用、位于两个面板之外、窄窗口展开计划仍可见、状态与产物不重叠以及未创建执行作业。它不会点击付费启动按钮。本轮用用户当前2048任务的副本验收，模型调用和派发数均为0。
