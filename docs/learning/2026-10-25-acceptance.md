# 0.2.0 本地验收记录

本记录汇总当前开发会话的实际命令结果，不是完整终端原始日志。

## 环境与边界

- 本机 Windows，Python 3.14，独立 `.venv`，editable 安装 agent-review-loop==0.2.0。
- 直接依赖固定为官方 mcp==2.3.0；当前解析到 Pydantic 2.14.1、AnyIO 4.15.1。
- 无模型调用、无账号密钥读取、无客户端现有配置修改。
- 本轮未运行真实编码 Agent；MCP 子进程由官方 SDK 管理。

## 最终检查

| 命令 | 实际结果 |
| --- | --- |
| `.venv/Scripts/python.exe -m unittest discover -s tests -v` | 19 项通过，最后一次 5.935 秒 |
| `.venv/Scripts/python.exe -m examples.task_demo` | 创建→领取→拒绝冲突→提交→重复提交→重启恢复，退出 0 |
| `.venv/Scripts/python.exe -m pip check` | No broken requirements found |

检查分组：原进程 8 项、共享存储 7 项、MCP/CLI 4 项。一个检查可以覆盖一条完整行为链，不以检查数量作为完整性证明。

MCP 检查实际启动两个独立 stdio 服务进程，协议分别为 2026-07-28 与 2025-11-25；同时竞争领取只出现一个成功，同时重复提交返回同一回执。关闭两个服务后第三个服务读取原结果，使用原 request_id 重试仍返回同一回执。

任务列表不含正文、提交摘要或领取 token；目录 JSON 实测 4359 UTF-8 字节。输入检查覆盖布尔任务 ID、过大分页、空标题、未知任务；存储检查覆盖错误凭据、过期尝试、版本冲突、不相关数据库、非数据库文件和更新版本的数据库。

## 开发中实际发现的问题

| 观察 | 定位与修复 | 复验 |
| --- | --- | --- |
| 最初存储检查报缺少模块 | 实现前先证明检查会失败，再加入存储实现 | 存储检查通过 |
| Windows 临时数据库清理失败 | 测试中的 sqlite3 事务上下文没有关闭连接，改为显式关闭 | 不再出现文件占用错误 |
| MCP 客户端没有结构化字段 | 核对安装版 SDK，显式声明结构化输出与返回类型 | 双协议检查读取 structured_content 成功 |
| 配置 JSON 重定向后中文解码失败 | CLI 显式使用 UTF-8 标准流 | 含中文临时路径的配置检查通过 |
| 较短续期可能缩短原期限 | 使用现有到期时间与新期限的较大值 | 续期与错误 token 检查通过 |

## 接入准备

本机 `.agent-review-loop/` 下已经生成 `workbuddy-mcp.json` 与 `codex-config.toml`，并创建了待领取的合成验收任务。配置中为同一数据库绝对路径；文件属于本机运行产物，不加入 Git。JSON 与 TOML 已解析检查。

生成配置不等于已导入客户端，准备任务不等于真实 Agent 已领取。接下来的真实验收需记录：客户端版本、发现的工具、创建/读取/领取/提交结果，以及另一客户端读取结果的证据。
